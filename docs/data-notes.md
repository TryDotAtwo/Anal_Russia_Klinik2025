## Данные и пути

Этот файл описывает **источники данных**, форматы файлов и важные пути. Любые изменения в данных нужно отражать здесь.

### 1. Основные файлы

- **Список препаратов для анализа**
  - Файл: `Bot_for_anal_rec/filtered_names_drugs_NEW.json`
  - Тип: JSON‑массив строк.
  - Использование: загружается в `Main.py` как `preparations`.

- **Чёрный список препаратов**
  - Файл: `Bot_for_anal_rec/blacklist_drugs.json`
  - Назначение: исходный «расстрельный список» с названиями, альтернативными названиями и описанием.
  - Формат (упрощённо):
    - `Название препарата`: строка,
    - `Альтернативные названия`: массив строк,
    - `Описание`: текст.
  - В пайплайне:
    - используется для построения автомата Ахо–Корасика (по основному и альтернативным названиям),
    - полная запись по препарату прикрепляется к результатам анализа как `blacklist_entry`.

- **База препаратов и доказательной информации**
  - Файл: `Bot_for_anal_rec/drugs.json`
  - Назначение: основная база по препаратам (ATX, MNN, критерии доказательности и т.п.).
  - Формат (упрощённо): массив объектов:
    - `kind`: список категорий,
    - `drug`: объект с полями `name`, `atx`, `quality`, `mnn`, `description`, `criterions` и др.
  - В пайплайне:
    - загружается в `Main.py` как `additional_drug_info`,
    - из неё строится словарь `additional_drug_dict` по имени и ATX‑коду,
    - для каждого найденного препарата полная структура `drug` и категории `kind` попадают в `additional_info` итогового JSON.

- **Клинические рекомендации (предобработанный JSON)**
  - Файл: `Bot_for_anal_rec/clinical_recommendations.json`
  - Формат: объект с `pdf_hash` и словарём `recommendations` (см. `Logic/Clinick_Extract.py`).
  - Может быть пересоздан при изменении PDF.

### 2. Выходные файлы

- **Результаты матчей по батчам**
  - Шаблон: `Bot_for_anal_rec/Match_Clinick_batch_{N}.json`.
  - Содержимое:
    - по каждой клинреке — список препаратов `drugs_mentioned`,
    - внутри каждого препарата:
      - `drug`: исходное название из батча,
      - `in_blacklist`, `blacklist_description`,
      - `blacklist_entry`: полная запись из `blacklist_drugs.json` (если препарат в списке),
      - `additional_info`: массив объектов, в т.ч.:
        - `kind` и полный объект `drug` из `drugs.json`,
        - агрегированные `points` по критериям (WHO, Cochrane, PubMed и др.),
      - `mentions`: контексты и результаты LLM‑анализа.

### 3. Правила изменения данных

- Любое изменение:
  - формата JSON,
  - расположения файлов,
  - стратегии разбиения на батчи
  
должно быть:

1. отражено в `core/config.py` (если меняются пути/ключи),
2. описано текстом в этом файле (`data-notes.md`),
3. при необходимости — задокументировано как решение в `decision-log.md`.
