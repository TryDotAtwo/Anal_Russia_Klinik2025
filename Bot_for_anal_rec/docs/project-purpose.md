## Цель и рамки проекта

### 1. Краткое описание

`Bot_for_anal_rec` — это инструмент для **автоматического анализа клинических рекомендаций**:

- извлекает текст из PDF клинреков,
- ищет в тексте упоминания лекарственных препаратов,
- сопоставляет найденные препараты с чёрным списком и дополнительными данными,
- проводит LLM‑анализ контекста упоминаний (уровень доказательности/убедительности, тип упоминания),
- сохраняет результаты в удобном для последующей обработки формате.

### 2. Основные пользовательские сценарии

- **Пакетный анализ списка препаратов**:
  - вход: JSON со списком препаратов (`filtered_names_drugs_NEW.json`),
  - выход: JSON‑файлы `Match_Clinick_batch_*.json` с результатами по батчам.
- **Повторный анализ при изменении данных**:
  - изменения в PDF, чёрном списке или данных о препаратах должны приводить к обновлению соответствующих артефактов (`clinical_recommendations.json`, итоговые матчи и т.п.).

### 3. Границы системы

- Система **не отвечает** за:
  - загрузку/поддержание самих клинических рекомендаций на внешних ресурсах,
  - интерпретацию результатов врачом,
  - принятие клинических решений.
- Система **отвечает** за:
  - технически корректный и воспроизводимый пайплайн анализа,
  - явное логирование прогресса и ключевых шагов,
  - аккуратную работу с форматами данных.

### 4. Ключевые требования к реализации

- **Прозрачность пайплайна**:
  - каждый крупный шаг должен быть выделен в отдельную функцию/модуль и описан в `pipelines.md`.
- **Масштабируемость**:
  - асинхронная обработка PDF и LLM‑запросов,
  - работа батчами по препаратам.
- **Отслеживание прогресса**:
  - выводить в консоль, сколько клинреков и упоминаний уже обработано.

### 5. Направления развития

- Улучшение качества извлечения упоминаний (морфология, контекст).
- Оптимизация запросов к LLM (группировка, кэширование).
- Улучшение объяснимости результатов и форматирования отчётов.
