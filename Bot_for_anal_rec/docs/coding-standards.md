## Стандарты кода и структуры

### 1. Общие принципы

- **Простота важнее абстракций**: не вводить лишних слоёв, если они не решают конкретную проблему.
- **Явность**:
  - имена функций и файлов должны отражать их роль в пайплайне,
  - конфигурация — централизованно в `core/config.py`.
- **Чистый корень репозитория**:
  - в корне — только `Main.py`, `docs/`, конфиги и директории пакетов.

### 2. Стиль Python

- Использовать **snake_case** для функций и переменных.
- Имена модулей — в нижнем регистре, без пробелов.
- Предпочитать **явные импорты** из модулей `Logic/`, `core/` и т.д.
- Логика одного шага пайплайна — в отдельной функции/модуле, а не внутри `main`.

### 3. Работа с конфигурацией

- Все пути и числовые параметры хранить в `core/config.py`.
- Не жёстко прошивать новые абсолютные пути в коде без отражения в документации:
  - любой новый путь/формат описывать в `data-notes.md`.

### 4. Логирование и прогресс

- Для долгих операций:
  - логировать **объём работы** (кол-во клинреков, упоминаний),
  - логировать **прогресс** (сколько обработано / сколько всего),
  - фиксировать ключевые метрики времени.
- Не использовать лишний «шум» в логах, который не помогает диагностике.

### 5. Тестируемость и разбиение

- Стараться делать функции **чистыми** (по возможности без побочных эффектов).
- Разбивать тяжёлые блоки на шаги:
  - извлечение данных,
  - трансформация,
  - запись результатов.

### 6. Документация изменений

- Любое нетривиальное изменение в архитектуре или поведении:
  - кратко описать в `operations-log.md`,
  - если это решение с альтернативами — зафиксировать в `decision-log.md`.
