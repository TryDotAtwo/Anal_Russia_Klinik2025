## Гайд для агентов

Этот документ описывает, **как должен работать агент** с проектом `Bot_for_anal_rec`.

### 1. Общий порядок работы

1. **Прочитать документацию**:
   - `docs/README.md`
   - `docs/agents-guide.md` (этот файл)
   - `docs/project-purpose.md`
   - `docs/architecture.md`
   - `docs/pipelines.md`
2. **Понять запрос пользователя** и выписать ключевые цели.
3. **Составить краткий план действий** (2–6 пунктов) и проговаривать его пользователю перед первым изменением кода.
4. **Выполнять изменения небольшими шагами**, после каждого шага:
   - запускать проверки/линтеры, если это уместно,
   - обновлять соответствующие логи в `docs/`:
     - изменения в коде/структуре → `operations-log.md`,
     - новые решения/договорённости → `decision-log.md`,
     - новые гипотезы/эксперименты → `hypotheses.md`,
     - важные запросы пользователя и их обработка → `interaction-log.md`.
5. **Финальный отчёт**: коротко описать, что сделано, какие файлы изменены, и что осталось на будущее.

### 2. Правила изменений кода

- **Не размазывать ответственность**:
  - весь запускаемый сценарий — в `Main.py`,
  - общая конфигурация и пути — в `core/config.py`,
  - отдельные шаги пайплайна — в `Logic/*`.
- **Сначала чтение, потом запись**:
  - перед изменением файла всегда читать его, не дописывать «вслепую».
- **Без комментариев-очевидностей**: комментарии только для нетривиальной логики, компромиссов или важных инвариантов.
- **Строгая работа с путями и данными**:
  - не зашивать новые абсолютные пути без необходимости,
  - описывать все чувствительные пути и форматы в `data-notes.md`.

### 3. Правила документации

- **Каждая крупная манипуляция** с кодом/структурой:
  - запись в `operations-log.md` с датой, кратким описанием, целями и затронутыми файлами.
- **Ключевые решения**:
  - фиксировать в `decision-log.md` (контекст → варианты → выбранное решение → аргументы).
- **Долговременная память агента**:
  - важные постоянные факты (нестандартные файлы, критические ограничения, особенности данных) заносить в `agent-memory.md`.
- **Взаимодействие с пользователем**:
  - сложные/длинные сессии кратко резюмировать в `interaction-log.md` (запрос → что сделали → результат/статус).

### 4. Что делать при неопределённости

- Если что-то неочевидно:
  - сначала поиск по коду (структура модулей, уже существующие паттерны),
  - потом — чтение соответствующих файлов в `docs/`,
  - только после этого — вопрос пользователю (если по-прежнему непонятно).

### 5. Приоритеты

1. **Корректность и воспроизводимость**.
2. **Прозрачность изменений** (логи и документация).
3. **Простота и расширяемость** решений.
